# 三国象棋（三叶六边形盘）自测报告

## 怎么测的

- 用 JavaScript 把[设计方案](设计方案.md)里的规则完整实现了一遍：走法、过河、中原三角、飞将、吃帅出局、吞并。代码在 `sim/` 目录，`node sim/test.js` 可以跑规则校验。
- 先做规则正确性检查：相邻关系对称、三家开局着法数相同、悔棋还原等，全部通过。
- 再让 3 个 AI 自己对下，一共 **1000 局**，比较 4 种规则组合。
  - AI 用的是三人棋常用的 Best-Reply Search：自己走一步，再假设两个对手里最狠的一步，再自己走，看 3 层，加上吃子延伸。
  - 和棋判定：150 步（每人走一次算一步）没有吃子，或者总共走满 600 步。
- 局限：AI 只会算子力，不会结盟、谈判、报复，也偏保守。所以下面的数字反映的是规则本身的结构倾向，不能代替真人试玩。

## 结果总表

| 规则组合 | 局数 | 魏/吴/蜀 胜率（魏先走） | 和棋 | 平均步数 | 第一个吃帅的人最终获胜 | 飞将吃帅占比 |
|---|---|---|---|---|---|---|
| **A. 吞并 + 飞将（原方案）** | 300 | 22% / 24% / 26% | **28%** | **267** | 78% | 22% |
| B. 移除 + 飞将 | 300 | 17% / 17% / 15% | 51% | 441 | 62% | 21% |
| C. 吞并 + 取消飞将 | 200 | 16% / 18% / 13% | 54% | 312 | 97% | 0 |
| D. 按位置瓜分 + 取消飞将 | 200 | 14% / 9% / 16% | 62% | 411 | 95% | 0 |

其他数据（以 A 为准）：

- 第一个出局的人：被两家合围（两家各自打掉了他 30% 以上的子）的占 62%。
- "捡漏"：吃帅的人打掉的子比另一家还少，占 40%。
- 中原三角很热闹：平均每局有 7.6 步穿过中原，其中一半以上是吃子。
- 开局第一步就"炮打马"的局有 12%，但这么走的先手胜率只有 25%，和不这么走差不多，不算漏洞。

## 优点

1. **座位很公平。** 三家胜率 22% / 24% / 26%，差距在 300 局的统计误差（约 ±5%）以内，先手没有明显优势。
2. **保留了象棋手感。** 开局三家各有 44 种走法，和普通象棋开局完全一样。每条前线的纵深也和原版相同，会下象棋的人可以直接上手。
3. **吞并让游戏能分出胜负。** 吞并比"直接移除"和棋少一半（28% 对 51%），对局短 40%（267 步对 441 步）。"移除"规则下最常见的情况就是大家都不敢动。
4. **中原是天然的焦点。** 双方在中原发生的冲突很多，三条中路联通，使得中局很有张力。
5. **飞将意外地重要。** 它贡献了约五分之一的吃帅。取消飞将以后，和棋从 28% 涨到 54%，第三方翻盘的机会也从 22% 掉到 3%。所以飞将应该保留。

## 缺点和解决方式

| # | 问题 | 证据 | 解决方式 |
|---|---|---|---|
| 1 | **规则漏洞：马绕过中原三角的跳法只有单向成立。** 例如魏马可以从 4 路河口跳到蜀 4 路河口，蜀马却跳不回来。 | 规则校验时发现，每国各有 4 个这样的跳法 | **已修正**：规定"马不能绕过中原三角跳"，只保留双向都成立的跳法。规则写法："中原三角不是格子，马的'日'字不能跨过或绕过它。" |
| 2 | **残局三家僵持。** 三家各剩一点子，谁先进攻谁就把后背亮给第三家，于是谁都不动。 | 方案 A 中 18% 的局三家都活着却和棋，这些局场上平均只剩全部子力的四分之一 | 加**限着计分**：50 回合没有吃子就终局，按"吃掉对方子的分值"排名，不按"剩下多少子"。这样进攻才有回报，龟缩会输。（还没模拟） |
| 3 | **滚雪球。** 吞并以后，第一个吃到帅的人 78% 最终获胜，第一次吃帅基本就决定了胜负。 | 表中"第一个吃帅的人最终获胜"一栏 | ① 按位置瓜分降兵**没用**（方案 D 仍是 95%），不推荐。② 推荐**降兵整编**：吞并来的子换色后**下一轮不能动**，给第三家一个反击窗口。③ 或者干脆用"首帅即终局"计分模式，承认第一次吃帅就是决胜点，把它当成一盘棋的高潮。（②③还没模拟） |
| 4 | **捡漏和围攻。** 62% 的出局者是被两家合围的；40% 的吃帅是"别人出力，我收尾"。 | 同上 | 这本来就是三国的味道，不需要全部消除。可以在计分模式里加"功劳分"：出局者被谁打掉的子多，谁就拿对应的分；吃帅只额外加固定的 10 分。这样出力最多的人不吃亏。 |
| 5 | **飞将可能被用来"拥立"。** 第三家挪开挡在中路的子，就能决定另外两家谁先飞将吃帅。 | 推断。飞将吃帅很多，但 AI 不会故意拥立，模拟测不到这一点 | 先保留飞将（它是减少和棋的主力），真人试玩时重点观察。如果确实出现拥立，就改成"飞将只能由轮到的一方主动吃，第三家移开挡子的那一轮不能被利用"，或者规定穿过中原不算照面。 |

## 推荐的修订规则（相比原方案）

1. 马不能绕过中原三角跳（已在引擎里实现）。
2. 保留飞将和吞并。
3. 新增：吞并来的子当轮不能动（降兵整编）。
4. 新增：50 回合无吃子即终局，按吃子分排名。

第 3、4 条可以接着在模拟器里测；更关键的是真人试玩，因为结盟、背盟这些因素 AI 测不出来。

## 第二轮：测试第 2、3 条修订（2026-10-03，600 局）

| 规则组合 | 局数 | 魏/吴/蜀 胜率（魏先走） | 和棋 | 三家僵持到终局 | 第一个吃帅的人最终获胜 |
|---|---|---|---|---|---|
| A. 原方案（吞并 + 飞将） | 300 | 22% / 24% / 26% | 28% | 18% | 78% |
| E. A + 降兵整编 | 200 | 22% / 26% / 25% | 28% | 21% | 76% |
| F. A + 限着计分 | 200 | 25% / 36% / 40% | 0% | 7% | 83% |
| G. A + 两条都加 | 200 | 28% / 31% / 41% | 0.5% | 8% | 84% |

说明：
- "三家僵持到终局"指 150 步没有吃子、三家都还活着就结束的局。
- 计分规则下，这种局按吃子分决出胜负，所以不算和棋。AI 的评估也改成了同时看子力和吃子分。

结论：
1. **限着计分有效**：和棋基本消失，三家僵持从 18% 降到 7%。因为吃子有分，AI 进攻明显更积极，第一次吃帅从平均第 170 步提前到第 134 步。**建议采用。**
2. **降兵整编无效**：第一个吃帅的人仍然 76% 获胜，和原方案差不多。吞并来的子哪怕一回合不能动，也照样能挡子、当炮架，而且吃帅的人子力已经大幅领先。**建议放弃。**
3. **滚雪球没有解决**：所有组合里，第一个吃帅的人都有 76% 到 84% 最终获胜。建议接受这一点，把第一次吃帅当成一盘棋的决胜高潮。如果还想压，下一步可以试"只吞并车、马、炮各一个，其余移除"。
4. **新问题：计分规则让最后行棋的一家占优**。F、G 两组里，蜀（第三个走）的胜率都在 40% 左右，魏（先走）只有 25% 到 28%；原方案没有这个现象。从吃帅记录看，大多数第一次吃帅都是"下家吃上家"：紧接着你行棋的人最先抓到你的破绽。计分让大家进攻更早，先走的魏也就最先暴露。这一条原因是推断。缓解办法：每局轮换座位（方案里本来就有），多局累计就能抵消；如果单局也想公平，可以给先走的两家各补几分，具体分值需要再测。

### 修订后的推荐规则

1. 马不能绕过中原三角跳。
2. 保留飞将和吞并。
3. **50 回合无吃子即终局，按吃子分排名**（吃掉的子按分值算，吃帅另加 10 分）。
4. 每局轮换先手座位。
5. 不加降兵整编。

## 复现

```
cd sim
node test.js                                  # 规则校验
node sim.js absorb 20 1 3 > out.jsonl         # 规则 局数 随机种子 搜索深度
node analyze.js out.jsonl                     # 统计
```

规则名可选 `absorb`、`remove`、`absorb-nofly`、`absorb-nofly-split`、`absorb-freeze`、`absorb-score`、`absorb-freeze-score`。所有对局原始数据在 `sim/results/`。
